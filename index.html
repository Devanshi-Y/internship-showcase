Two months, one question: can a mathematically secure cipher be broken by measuring the chip that runs it? I built AES-128 from scratch in C, then recovered its full 128-bit key from real power traces using Correlation Power Analysis.

Try it: Hamming weight

Click bits. Power is modelled as proportional to the number of 1s.

Byte = 0x00 · decimal 0 · HW = 0

From class: 0x05 → HW 2, 0x0A → HW 2 (same power), 0xBA → HW 5.

Pearson correlation (from class)

ρ = Σ(xᵢ − x̄)(yᵢ − ȳ) / ( σₓ · σᵧ )

x = measured power at one sample point (one value per trace), y = predicted Hamming weight of S-box(plaintext ⊕ key guess). Done for 256 guesses × 5,000 sample points: the covariance_LT matrix.

Parallel CPA

RunWorkersSerialParallelSpeed-up
First run613.74 s8.83 s1.56×
Second run140.74 s4.16 s0.18×

The key was identical in both runs. When the whole serial job takes under a second, process start-up and data copying cost more than the work they share, so parallelism helps only for large enough workloads.

Timing channel: negative result

30,000 trials per plaintext value: cache-line group means span about 108 ns, below the ~138 ns noise. No exploitable timing leak in this virtualised setup, while power gave the key within a few hundred traces.
